How it works

Real components, not mockups of them.

A motion designed on a drawing of your button never quite fits the button. Motioneer works on the thing itself, with its own markup and its own stylesheet.

1

Point it at what is running

Give it the address of your dev server or a deployed site. It proxies the page so the picker can read the document, and a bookmarklet covers pages that need you signed in.

localhost:3000
2

Pick an element off the page

Hover, widen to the parent or narrow to a child, then capture. The capture keeps the styles that matter to that element and freezes its images, so what you animate is what you ship.

3

Compare three treatments

Say what the motion is for: an entrance, an emphasis, an idle, or a response to a press. You get a subtle, an expressive and a bold reading of it, all on one clock, so the differences are visible rather than remembered.

Film

From the motions you kept to a film you can send.

A product demo is a minute of components arriving a beat apart. The film editor sequences what you kept on one timeline, with titles, sound and a camera move, and renders an MP4 on your machine.

  • A first cut in one click. Opening, feature highlights, and a moment to land, all yours to edit.
  • Linked starts. A clip can begin when another ends, so reordering one does not mean retiming all of them.
  • Preview equals export. Frames are rendered from the same composition the editor shows, and the suite compares them pixel by pixel.

What gets judged

Every motion passes the gates before you see it.

A model writes the css. The studio reads it back and refuses what would break in your product, so the three you compare are three that would ship.

  • Only transform and opacity move. Animating layout drops frames, so a sheet that animates width or margin is sent back.
  • Scoped to the element. Keyframe names are namespaced, because a sheet defining rise would replace whatever your app already called rise.
  • Reduced motion respected. Every motion is wrapped in the media query, since a person who asked for less should get less.
  • Checked in a real browser. The element is rendered with the motion applied and watched for blank frames, escapes from its box, and content that never settles.
/* expressive, 0.8s, entrance */
@media (prefers-reduced-motion: no-preference) {
  [data-mn-pricing] > * {
    animation: mn-pricing-arrive 720ms cubic-bezier(.2,.9,.3,1.1) both;
  }
  [data-mn-pricing] > :nth-child(2) { animation-delay: 70ms }
  [data-mn-pricing] > :nth-child(3) { animation-delay: 140ms }
  @keyframes mn-pricing-arrive {
    from { opacity: 0; transform: translateY(14px) }
    to   { opacity: 1; transform: none }
  }
}
Agents

Your coding agent can ask for motion too.

Motioneer ships a Model Context Protocol server. An agent working in your codebase can hand it a component and get back css that already passed the gates, or open the studio for you when a decision needs eyes.

  • Same gates, same taste. The server calls the functions the studio calls, so an agent cannot get a motion the studio would have refused.
  • Bring your own model. The Claude command line, or any provider with an API key. Keys stay in a file on your machine.
# once, for every project
claude mcp add --scope user motioneer -- npx -y -p motioneer motioneer-mcp

# then, in a conversation
> give the pricing card an entrance, subtle, about half a second
